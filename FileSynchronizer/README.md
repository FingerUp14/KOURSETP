# Синхронизация файлов

Java-приложение для двусторонней автоматической синхронизации файлов в двух каталогах по TCP. На каждом компьютере запускается один экземпляр: он одновременно принимает входящие соединения и периодически соединяется со вторым экземпляром.

## Возможности и правила

- Отсутствующие файлы, в том числе во вложенных каталогах, копируются в обе стороны. Данные передаются потоково, а их SHA-256 проверяется после приёма.
- Файлы с одинаковым относительным путём и разным содержимым считаются конфликтом: обе версии остаются на месте, пути и хэши записываются в журналы. Выберите нужную версию вручную, пока синхронизация остановлена, после чего запустите её снова.
- Проверка выполняется автоматически через заданный интервал; её также можно запустить кнопкой. Если второй экземпляр ещё не запущен, соединение повторяется позже.
- Удаления не распространяются: отсутствующий файл будет скопирован снова. Пустые каталоги отдельно не передаются. Символические ссылки не синхронизируются.
- Каталог `.filesynchronizer-tmp` в корне каждого синхронизируемого каталога зарезервирован для временных файлов и исключён из обмена. Путь к собственному журналу также исключается из сканирования. Имена с обратной косой чертой или двоеточием не поддерживаются из-за различий файловых систем.
- Защиты соединения паролем и шифрования нет: используйте программу только в доверенной сети. Разрешите входящие TCP-соединения на выбранных портах в настройках сети.

## Сборка и тесты

Нужны JDK 17 или новее и Maven 3.8 или новее. Из каталога `FileSynchronizer`:

```console
mvn clean
mvn test
mvn package
```

Для полного цикла можно выполнить `mvn clean package`. Получаются исполняемый `target/FileSynchronizer-1.0.jar` и архив тестов `target/FileSynchronizer-1.0-tests.jar`. Приложение использует стандартную библиотеку Java. JUnit 5 применяется только для тестов и не входит в исполняемый JAR; его использование следует согласовать с преподавателем как стороннюю тестовую библиотеку. Maven Surefire запускает тесты на этапе `test`. Сетевым тестам требуется соединение с `127.0.0.1`.

Тесты проверяют SHA-256, снимок каталога, план синхронизации, защиту от некорректных путей и повреждённых данных, одновременное получение разных версий, обмен по TCP, журнал и автоматическое повторение синхронизации.

## Графический интерфейс

Запустите на обоих компьютерах:

```console
java -jar target/FileSynchronizer-1.0.jar
```

1. Выберите существующий доступный для записи каталог. Каталоги на двух компьютерах должны быть разными.
2. Введите адрес второго компьютера, локальный порт, порт второго компьютера и интервал в секундах. Например, у первого экземпляра порты `5000` и `5001`, у второго — `5001` и `5000`. При проверке на одном компьютере введите адрес `127.0.0.1` в обоих окнах.
3. Нажмите **«Подключиться»** в обоих окнах. Первый экземпляр будет повторять попытку, пока второй не запущен. После проверки соединения кнопка синхронизации станет доступна.
4. Нажмите **«Синхронизировать»**. После первой проверки последующие выполняются автоматически через указанный интервал. Ход работы и конфликты отображаются в журнале. Для завершения нажмите **«Остановить»** или закройте окно.

Журнал сохраняется в `sync.log` относительно текущего рабочего каталога. При двух экземплярах в одной папке сообщения записываются в общий журнал. Снимок каталога хранится в `.filesynchronizer-tmp/snapshot.properties`, загружается при запуске и обновляется при сканировании.

## Командная строка без графического интерфейса

Для первого компьютера:

```console
java -jar target/FileSynchronizer-1.0.jar --directory "C:\sync-a" --local-port 5000 --peer 192.168.1.20 --peer-port 5001 --interval 10
```

Для второго компьютера задайте его каталог, локальный порт `5001`, адрес первого компьютера и порт `5000`. Можно указать `--log путь/к/журналу.log`. Для одной попытки вместо постоянной работы добавьте `--once`: второй экземпляр к этому моменту должен быть запущен; при ошибке процесс завершается с ненулевым кодом. Справка: `java -jar target/FileSynchronizer-1.0.jar --help`. Постоянно работающий экземпляр завершается сочетанием Ctrl+C.

Отчёт и отдельная функциональная спецификация находятся в каталоге `report/`. Чтобы собрать PDF из TeX, перейдите в этот каталог и выполните `pdflatex report.tex` дважды (для оглавления и ссылок), а затем `pdflatex functional-specification.tex`. Потребуется дистрибутив TeX с русскоязычными пакетами. Титульные данные нужно заполнить; согласование спецификации с преподавателем выполняется отдельно.
